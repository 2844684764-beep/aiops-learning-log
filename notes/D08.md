### 3. `build_index.py`：切块 → 嵌入 → 入库

几个关键设计（都在脚本注释里）：

- **按 `##` 二级标题切**，不按固定长度硬切 —— 每一块都是语义完整的一小节。
- **80 字以下丢掉**（这种块多半只剩标题，进库只会制造噪声）；**800 字以上**再按空行段落二次切。
- **每 32 条一批**调 `embeddings`，避免单请求过大被限流。
- **每次重建先 `rmtree(chroma)`**，防止重复入库把同一个块塞进去两遍。
- 元数据只存 `{source, chunk}`，id 用 `文件名#序号` —— 后面 citations 直接回填这个，就能做到"每句话点回原文"。

产出：`corpus_stats.json` = `{"chunks": 130, "sources": 16}`，`chroma/` 约 2.4MB。

## 二、今天踩的坑（每条都能原文复现）

### 1. `import chromadb` 直接崩：sqlite3 版本太低（今天最大的坑）

**现象**：`python build_index.py` 连第一行都过不去：

```
RuntimeError: Your system has an unsupported version of sqlite3.
Chroma requires sqlite3 >= 3.35.0.
```

**根因**：`python -c "import sqlite3; print(sqlite3.sqlite_version)"` → **3.34.1**，RHEL 9.6 自带的；而 chromadb 1.5.9 硬性要求 ≥ 3.35.0。RHEL 的 sqlite 是系统组件，升级会牵连太广，不能动。

**解法**：装预编译的 `pysqlite3-binary`（自带一份新的 sqlite），在**任何 `import chromadb` 之前**把系统模块顶掉：

```python
__import__('pysqlite3')
sys.modules['sqlite3'] = sys.modules.pop('pysqlite3')
```

两个坑中坑：

- 这 5 行必须在文件最上面，`import chromadb` 之后再打等于没打。
- `sys.modules.pop('pysqlite3')` 不能省，否则内存里留着两份 sqlite 模块，chromadb 后面的动态 import 还可能走回旧的。

### 2. 把 root 的笔记复制进 `corpus/`，走了两条弯路

- `cd /root/D*.md aiops/corpus` → **cd 只接受一个目录参数**，多参数直接报错（当时的错误直觉：以为 cd 能像 cp 一样吃文件列表）。
- `sudo cd /root` → **看着成功，目录没变**。`cd` 是 shell 内建命令，`sudo` 起的是子进程，子进程 cd 完就退出，父 shell 还在原地。
- **正解**：`sudo cp /root/D*.md corpus/` —— 需要的是"读 root 文件的权限"，不是"让 shell 站到 root 目录"。

> 一句话记住：**`cd` 是内建命令，`sudo` 对它无效；跨目录搬文件用 `cp`，别改自己的落脚点。**

### 3. 拉 Google SRE Book 要走镜像

`git clone https://github.com/songjiayang/google-sre-book.git` 卡在连接；换成

```bash
git clone https://mirror.ghproxy.com/https://github.com/songjiayang/google-sre-book.git
```

秒下。

### 4. 嵌入模型名必须显式兜底（最隐蔽的坑）

`search_test.py` 一开始只读 `os.environ["EMB_MODEL"]`，`.env` 里少写就 KeyError。改成 `os.environ.get("EMB_MODEL", "BAAI/bge-m3")`，并和 `build_index.py` 用**同一个默认值**。

为什么强调同一个：建库用一个模型、查询用另一个模型，**两个向量空间对不上，检索结果会全是噪声，而且不报错**。这类"静默错"最难查，只能靠"两边共用一份配置"从根上杜绝。

### 5. 小尾巴

- `vim` 有一次非正常退出，留下 `.build_index.py.swp`；确认内容已存盘后删掉。
- `chroma/`、`corpus_stats.json` 是生成物，进 `.gitignore`；能进仓库的是脚本 + 语料清单。

## 三、认知升级

1. **切块策略比换模型重要**。固定长度硬切会把"看什么 → 异常是什么 → 下一步做什么"劈成两半；按 `##` 切，Top1 直接就是 D06 里"服务起不来"那完整一节。语义完整了，向量才有得比。
2. **向量库是编译产物，不是源码**。2.4MB 二进制 + 每次重建 → 必须 gitignore。能进仓库的是"切分脚本 + 语料清单"，别人 `python build_index.py` 就能复现。
3. **检索会"凑满 K 条"**。5 条里至少有 1 条不相关，但距离只差 0.006。所以光有 RAG 不够 —— **模型不会自己说"我不知道"，得靠评测逼它说**。这就是 D10 要造 5 条无答案题、D11 要算 recall@5 的原因。
4. **口语提问 + 书面语料**才是真实场景。这次故意不用语料里的词，仍然召回 D06/D02，语义检索的意义就在这。

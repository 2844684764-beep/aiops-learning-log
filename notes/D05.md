## 坑 1：网卡上加了延迟，但测不出来

### 现象

网卡是 `ens33`（不是手册早期写的 `ens160`）。在 `ens33` 上加 `netem delay 200ms` 后：

```bash
curl -w "%{time_total}s" -o /dev/null -s localhost:8000/        # 还是 0.01s
curl -w "%{time_total}s" -o /dev/null -s 192.168.223.129:8000/  # 还是 0.01s
```

加在 `lo` 上才看到延迟。

### 原因

**`tc qdisc` 只对「从这块网卡出去」的包生效（egress）**，而这两个地址都不走 `ens33`：

| 目标 | 内核怎么走 | 经过 ens33 吗 |
|---|---|---|
| `localhost` / `127.0.0.1` | 查路由表 → `lo` | ❌ |
| `192.168.223.129`（本机 IP） | 本机地址会被内核内部回环，也走 `lo` | ❌ |
| 外网（如 `mirrors.ustc.edu.cn`） | 默认路由 → `ens33` | ✅ |

所以：**你在 ens33 上排队，但包根本没从 ens33 走。**

### 三种正确测法

**A. 加在 lo 上**（模拟本机延迟，最直观）

```bash
sudo tc qdisc add dev lo root netem delay 200ms
curl -w "耗时: %{time_total}s\n" -o /dev/null -s localhost:8000/
sudo tc qdisc del dev lo root          # 必须撤销
```

**B. 加在 ens33 上，但测外网**

```bash
sudo tc qdisc add dev ens33 root netem delay 200ms
curl -w "耗时: %{time_total}s\n" -o /dev/null -s https://mirrors.ustc.edu.cn
sudo tc qdisc del dev ens33 root
```

**C. 从客户端方向制造延迟**

在 Windows 上对 VM 做限速，或者用 `netem` 的 `ifb` 做 ingress（高级用法，暂时不用）。

### 怎么确认撤销干净了

```bash
tc qdisc show dev lo       # 正常应为 noqueue
tc qdisc show dev ens33    # 正常应为 fq_codel
```

看到 `netem` 就是没删。**留着不删，后面所有调试都会变慢，很容易误判。**

## 坑 2：2G 文件只占了 6%

### 现象

```bash
fallocate -l 2G /tmp/bigfile
df -h /        # 从 14% 变成 20%，只涨了 6%
```

### 原因

算术是对的：**根分区总共 36 GB**，2 / 36 ≈ 5.6%，四舍五入就是 6%。

不是 `fallocate` 没生效，也不是「内存太大」——是分母太大。

### 正确的造法

**A. 直接写满根分区（不推荐）**

```bash
fallocate -l 28G /tmp/bigfile
df -h /
rm -f /tmp/bigfile
```

> 根分区写满会连锁反应：systemd 起不来、日志写不进、SSH 可能异常。
> **别拿系统盘做这种实验。**

**B. 造一个小文件系统（推荐）**

```bash
fallocate -l 200M /tmp/small.img       # 200MB 镜像
mkfs.ext4 -q /tmp/small.img
sudo mkdir -p /mnt/small
sudo mount -o loop /tmp/small.img /mnt/small

df -h /mnt/small                        # 200M
sudo dd if=/dev/zero of=/mnt/small/fill bs=1M 2>&1 | tail -1
df -h /mnt/small                        # 100% ✅

# 清理
sudo rm -f /mnt/small/fill
sudo umount /mnt/small
rm -f /tmp/small.img
```

几秒就能造出 100%，而且炸的不是系统盘。`loop` 设备在真实运维里也常用来做隔离测试。

## 今天真正理解了什么

- **`tc` 是单向的**：只管出、不管进；只对经过指定网卡的流量生效
- **`localhost` 和本机 IP 都不走物理网卡**，它们走的是内核的本地路由
- **观察类问题的第一步是算比例**：2G/36G=6%，先怀疑自己的期望，再怀疑工具
- **造故障要选对「爆炸半径」**：能在小容器里炸，就别炸系统盘

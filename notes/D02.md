## 今天踩的 5 个坑（都很典型）

### 坑 1：忘记启动 uvicorn，Prometheus target 是 DOWN

**现象**：Grafana 一片空白，Prometheus 的 Targets 页面 `aiops-app` 显示 **DOWN**。

**排查**：Targets 页面右边有一列 `Last Error`，一般写 `connection refused`。

**原因**：服务根本没在跑。Prometheus 每 15 秒去敲门，没人应答。

**解决**：`uvicorn app:app --host 0.0.0.0 --port 8000`

**以后怎么避免**：**监控没数据，先确认被监控对象活着**，再看监控本身。

```bash
ss -tlnp | grep 8000          # 端口在听吗
curl localhost:8000/metrics    # 本地能取到吗
```

这两条都通，才轮到怀疑 Prometheus。

> 真实生产里这个判断顺序更重要：告警说「服务挂了」，可能是服务真挂了，也可能是探针挂了。搞反方向会浪费半小时。

### 坑 2：面板编辑器报 `insertBefore` 错误

**现象**：点「Add visualization / 配置可视化」，界面报

```
NotFoundError: Failed to execute 'insertBefore' on 'Node':
新节点要插入的节点不是该节点的子节点
```

**原因**：Grafana 13.3.1 前端的 React 渲染 bug，和我们的数据、配置无关。

**解决**：不点界面，改用 **provisioning**——把仪表盘写成 JSON 文件，Grafana 启动时自动加载。

```yaml
volumes:
  - ./dashboards:/var/lib/grafana/dashboards:ro
  - ./provisioning/dashboards.yml:/etc/grafana/provisioning/dashboards/aiops.yml:ro
```

**额外收获**：这套做法本身比点界面更好——可版本控制、可复现、换机器一条命令还原。

### 坑 3：容器读不到挂载目录，`permission denied`

**现象**：

```
failed to provision dashboards: open /var/lib/grafana/dashboards: permission denied
```

**原因**：Grafana 容器里以 **uid 472** 运行，而宿主机的 `/home/shawny` 是 `700`，容器用户连目录都进不去。

**解决**：

```bash
chmod 711 /home/shawny                    # 允许穿越（不能列目录）
chmod -R a+rX ~/aiops/dashboards ~/aiops/provisioning
```

**记住这条**：容器里的用户和宿主机的用户不是同一套 uid。挂载任何目录前先想「容器里的进程是谁，它读得到吗」。

### 坑 4：带标签的指标，重启后「消失」

**现象**：服务重启后，`/metrics` 里 `app_*` 一个都没有，只有 `python_gc_*`、`process_*`。

**原因**：

```python
REQUESTS = Counter("app_requests_total", "请求总数", ["path", "status"])
```

这行只是**声明**。带标签的指标必须等 `REQUESTS.labels("/", "200").inc()` **第一次执行**，才会创建出真正的样本。没有流量 = 没有子指标 = 导出为空。

**解决**：打点流量就有。

```bash
for i in {1..40}; do curl -s -o /dev/null localhost:8000/; done
```

**以后怎么避免**：学习期间开个常驻流量（见 `src/monitoring/traffic.sh`）。

### 坑 5：`image: latest` 是个隐藏的地雷

**现象**：拉下来的是 13.3.1，但没人知道明天会变成什么版本。

**风险**：大版本升级会改仪表盘 JSON 结构，某天重建容器，你的面板可能就打不开了。

**解决**：锁版本号。

```yaml
image: grafana/grafana:13.3.1
```

## 今天真正理解了什么

- **Prometheus 是 pull 模型**：它主动来抓，所以「被监控对象」必须一直活着
- **容器里没有 localhost**：`host.docker.internal` + `extra_hosts` 是宿主机的入口
- **P95 比平均值有用**：100 个请求 99 个 10ms、1 个 5 秒，平均值看不出来，P95 能
- **配置即代码**：能写成文件的就别点界面
